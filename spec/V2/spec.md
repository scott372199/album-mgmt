## 0. 一句话

把三个云和一个 CI 系统里的事实收进一个**只读的决策台**：资源按「站点 → 层」组织并串成图，成本按统一口径摊到图上的节点，漂移与发布挂在同一个节点上；平台**从不写云、从不执行 apply**，只负责让人在三分钟内看懂"现在是什么、钱花在哪、哪里偏了、下次改动会碰什么"。

*One read-only console: resources organised as sites and layers, wired into a graph; cost allocated onto the same nodes; drift and releases attached to them. The console never writes to the cloud and never runs an apply — it exists so a human can answer four questions in three minutes.*

## 1. 目标与成功标准 / Goals and Success Criteria

### 1.1 目标 / Goals

1. **一个入口回答四问**：这个东西属于谁、谁依赖它、它花了多少钱、它上次被谁改。
   *One screen answers: who owns it, who depends on it, what it costs, who last changed it.*
2. **成本能对得上账**：任何页面上的金额都能追到账单行，差额能被逐类解释。
   *Every number on screen traces back to a bill line, and any gap is explained line by line.*
3. **偏离能看见**：线上与代码不一致时，人比事故先知道，而且知道差在哪个属性。
   *Drift surfaces before an incident does, down to the attribute.*
4. **改动能追溯**：一次 apply 改了哪些资源，谁批的，风险在哪。
   *One apply maps to a set of changed resources, an approver and a risk level.*
5. **平台自身不成为风险**：只读、可降级、断一个数据源仍然可用。
   *Read-only, degradable, still usable when one data source dies.*

### 1.2 成功标准 / Success criteria

| # | 指标 | 现状 | 目标 |
| --- | --- | --- | --- |
| S-1 | 回答"某资源属于哪、谁依赖、多少钱、谁改的"所需点击数 | 4 个控制台 + 人工翻 state | **≤ 3 次点击**，且在同一页面内完成 |
| S-2 | 月度成本可查时间 | 手工拉账单，T+7 之后 | **T+2 内**，且标注精度 |
| S-3 | 未分配成本占比 | 无分摊，100% 未分配 | **< 2%**，且必须单独可见 |
| S-4 | 漂移检出到可读结论 | 无 | 每日一次全量，**误报 < 5%** |
| S-5 | 一次 apply 到平台可见 | 无 | **≤ 5 分钟** |
| S-6 | 单数据源故障时页面可用性 | — | 其余数据源**全部正常**，故障源显式降级，不出现空白页 |
| S-7 | 平台对云的写权限 | — | **0 个写权限**（只读角色与一次 dispatch 例外） |

## 2. 范围 / Scope

EARS 记法：**当**（事件）/ **在 … 时**（状态）/ **若**（异常）/ **必须**（shall）。

### 2.1 全局框架

#### FR-01 全局壳与导航

**当**用户打开平台时，系统**必须**给出一个固定壳层：顶栏、侧栏、内容区，并让当前位置始终可见。

- 顶栏四项：站点选择（全部 / 单站）、账期与口径（成本相关页生效）、**数据时间**徽标、当前用户。
- 数据时间徽标显示最近一次成功采集的相对时间（如「12 分钟前」），点击展开三云与 CI 各自的最后成功时间；超过预期频率 3 倍未更新时变为琥珀色警示。
- 侧栏固定三组：**运营**（总览 / 资源目录 / 栈图谱 / 成本）、**治理**（发布 / 漂移 / 安全 / 容灾矩阵）、**响应**（告警与事件）。
- 导航项右侧的计数徽标**只**显示 `CRITICAL` 级未处理数；其余级别用灰点，不显示数字。
- **若**页面数据源进入降级，**必须**在内容区顶部出现横幅，点名数据源与最后成功时间；降级横幅不可手动关闭。

**验收**
- 任意页面，侧栏当前项有明确选中态；浏览器前进后退可回到上一页，URL 与页面一致。
- 把系统日期改到两天后（模拟采集停止），数据时间徽标变琥珀色，hover 说明超期时长。
- 断掉一个数据源后，所有页面仍能渲染，横幅只出现一次（不叠三条）。

#### FR-02 总览

**当**用户进入平台时，系统**必须**先给一句结论，再给证据，最后给待办。

- 结论条（一句话）：本期成本与环比、最大异常、待办条数。文案由数据生成，不用固定模板套数字。
- 四个指标卡：月成本、未处理 `CRITICAL` 漂移数、发布成功率（近 30 天）、待办数。每卡可点击，跳到对应页面并**携带当前筛选条件**。
- 成本趋势为主图（全宽，12 个月），支持三口径切换；图下一行状态条显示三云与三站点的健康状态。
- 「异常与待办」一张宽卡：左侧四个治理指标（漂移、安全、覆盖率、发布），右侧四条待办，每条**必须**标注它由哪个指标触发，可点进来源。
- 成本构成与节省建议并列两栏，节省条目必须显示估算依据，不提供"一键执行"。

**验收**
- 首屏（1440×900 不滚动）能看到结论条、四个指标卡与主图的上半部分，不出现三张以上并列小卡。
- 点「未处理 CRITICAL 漂移」→ 落在漂移页且筛选为 `CRITICAL`，URL 可复制分享，他人打开得到同一视图。
- 切换口径后，主图 Y 轴重绘且出现短暂提示「口径已切换」；X 轴刻度位置不变。
- 四条待办都能点进来源；任一条无来源时不显示。

### 2.2 资源目录与图谱

#### FR-03 资源列表与筛选

**在**浏览资源时，用户**必须**能在一个列表里按站点、层、云、类型、状态、关键词组合筛选，并始终知道筛掉了多少。

- 列表每行固定八列：名称、云、canonical 类型、站点/层、状态、月成本、漂移数、最近采集时间。
- 筛选区与结果区始终显示「命中 N / 全部 M」；**不得**只显示命中数。
- 支持三种视图：列表（默认）、域树、按层。三视图共享同一筛选条件。
- `canonical_type` 未映射的资源整行淡化，类型列显示「未映射」；层归属由推断得到的，层名加虚线下划线，hover 说明来源。
- **若**某云数据过期，该云的行显示过期标记，且不参与"最近采集"排序的默认值。

**验收**
- 组合三个筛选条件后，命中数与实际行数一致，"全部 M"不随筛选变化。
- 树视图展开到叶层，节点右侧显示资源数与月成本；无成本数据时显示「—」，不显示 0。
- 排序只允许六列（名称、类型、层、最近采集、月成本、漂移数），点其他列无反应。
- 2000 行数据下列表滚动流畅，不出现整表重排。

#### FR-04 资源详情

**当**用户点开一个资源时，系统**必须**在同一页右侧给出抽屉，不跳走、不丢筛选。

- 抽屉分区：基本信息（云、账号、区域、metro、所属站点/层）、标签（规范标签与原始标签分开列）、属性变更历史（最近 10 次，显示变了哪些字段）、成本（近 3 个月，按口径）、未关闭漂移、未豁免安全结论、最近变更事件。
- 每一块都**必须**标出数据来源与时间；缺失时显示「无数据 · 原因」，不留空。
- 标签区对**规范键缺失**要显式标红并给出补齐建议；对大小写冲突给出提示。
- 抽屉可通过 URL 还原（带资源标识），刷新后仍在。

**验收**
- 从列表第 5 页第 3 行打开抽屉，关闭后仍在第 5 页，筛选与滚动位置不变。
- 复制抽屉 URL 到新标签页打开，内容一致。
- 属性历史中任一条可展开看到"改前 / 改后"两个值。
- 无成本数据时该区块显示「该资源未出账」，不显示 0 元。

#### FR-05 站点与层结构

**在**任何涉及"层"的地方，系统**必须**使用同一套层标识与顺序：`s00-account`（共享）+ 每站点 `00-bootstrap / 01-storage / 02-data / 03-compute / 04-edge`。

- 层的编号**就是** apply 顺序：编号小的先 apply；站点之间可并行，站点之内串行。
- 站点与层清单来自仓库中每站的清单文件；清单不合法（编号不连续、层类型非法、依赖指向自身或更大编号）时，该站点标为"清单异常"并**拒绝**展示其层结构，**不得**猜测。
- 域树视图按「云 → 账号/订阅/项目 → 站点 → 层」展开；Azure 多一层资源组，同样展示。
- 未归入任何层的资源集合单列为「未归类」，并计入所有分母。

**验收**
- 四个站点、16 个层全部可见，顺序与上表一致；`02-data` 出现在 `03-compute` 之前。
- 人为把某站清单里两层编号改成相同，该站显示"清单异常"并给出具体原因。
- 「未归类」不为零时，目录页与总览都能看到它，且不隐藏。

#### FR-06 栈图谱

**当**用户打开图谱页时，系统**必须**画出站点与层的关系图，并让人一眼看出哪条关系是"代码写死的"、哪条是"猜的"。

- 节点 =（站点，层）。节点上显示层名、层类型、资源数、月成本。
- 边**必须**携带来源等级与证据文本，图例常驻：
  - 结构（同站点层号相邻且声明依赖）与 `remote_state` 引用为**最高可信**，实线；
  - 资源引用、配置引用为**中可信**，细实线；
  - 观测流量为**推断**，虚线；
  - 仅标签相同为**弱推断**，点线且**默认不画**，页面提示「另有 N 条推断关系」，可展开。
- 边方向恒为「被依赖 → 依赖」。跨站点只允许指向共享层。
- 提供三个视图：**分层**（全部边，按层号分带）、**数据流**（只留数据流经的边，基座层淡化）、**成本**（节点按成本着色并在底部画占比条，只留结构关系）。三视图共用同一分层布局，节点集合一致，只切换可见边与节点编码。
- 选中节点后，无关节点淡化，右侧面板给出：所属站点、层类型、层号、资源数、月成本、**影响面三跳**（每个被影响节点都能展开）、直接依赖与被依赖清单。

**验收**
- 16 个节点、12 条以上结构或 `remote_state` 边；任取 3 条边都能在右侧面板看到证据文本，且证据指向具体文件或配置项。
- 展开「推断关系」后弱边出现，收起后消失；展开状态不影响其他视图。
- 选中 `photos/01-storage`，影响面第一跳包含 `02-data` 与 `03-compute`。
- 图在 1280 宽下不出现节点重叠、连线穿框、文字溢出；视图切换时节点位置不跳动，只换可见边与编码。

#### FR-07 图谱健康度

**在**查看图谱时，用户**必须**能看到这张图本身有多可信：孤立节点、断边、关系等级分布、覆盖层数。

- 四项指标可点，点开落到对应清单（孤立节点列表 / 断边列表 / 按等级分组的边 / 未覆盖的层）。
- 「断边」定义：依赖指向的层已不存在或已不在清单中。
- 覆盖层数为「有资源且有关联的层 / 全部层」，未覆盖的层要点名。

**验收**
- 人为删除清单里的一层（模拟层消失），依赖它的边变断边，指标与清单同步。
- 四项指标相加不产生矛盾（如节点数 = 孤立 + 有边）。

### 2.3 成本

#### FR-08 口径与汇总

**在**查看任何金额时，系统**必须**同时显示口径（`BILLED` 发票 / `AMORTIZED` 摊销 / `ALLOCATED` 分摊）与精度（汇总 / 明细 / 摊销），缺任一项视为缺陷。

- 默认口径为 `ALLOCATED`。切换口径时，页面所有金额一起变，且**不得**混用。
- 汇总支持按站点、层、服务大类、云、资源类型分组；分组结果必须给出占比与环比。
- 「未分配」**必须**单独一行出现，即使为 0 也显示 `0.0%`；**不得**摊进任何分组。
- **若**某云某账期数据为暂定（缺行或与官方汇总偏差超过 1%），该账期标「暂定」，并在页面上说明"总额不含某云完整明细"。

**验收**
- 任一金额旁都能看到两个徽标；把页面截图给第三人，他能说出这个数字是什么口径。
- 切到 `BILLED` 后，未分配行消失（发票口径无分摊），页面给出解释而不是留空。
- 暂定账期时，页面顶部有说明条，且导出的文件里也带这条说明。

#### FR-09 趋势

**当**用户查看成本趋势时，系统**必须**支持按日/按月、按口径切换，且切换后**不能**让用户误以为成本变了。

- 切换口径时 X 轴刻度位置不变，只重绘 Y 轴与线，并出现 ≤3 秒的「口径已切换」提示。
- 线最多 6 条；超过时提示用户先聚合，不自动截断。
- 悬浮显示该点金额、口径、精度、账期状态。
- 无数据的时间段断开显示，**不得**用 0 连接。

**验收**
- 连续切换三次口径，X 轴刻度不移动，图形有过渡无闪烁。
- 某月无数据时该段为空白并有「无数据」标记，不出现 0 值折点。

#### FR-10 差异桥

**当**用户从发票口径切到分摊口径时，系统**必须**用一座"桥"逐类解释差额，而不是给一个差值。

- 五类差额固定：未分摊共享成本、承诺折扣未摊销、跨期调整、税费、汇率差。每类给出金额与占比。
- 五类之和**必须**等于「发票总额 − 分摊总额」，不等时页面显式提示「差额未完全解释」并显示残差。
- 每类可展开到构成它的账单行。

**验收**
- 五类金额相加等于差额（误差为 0）。
- 人为构造一个未归类差额，页面出现"未完全解释 + 残差金额"，不静默通过。
- 任一类展开后行数与该类金额一致。

#### FR-11 分摊明细

**在**查看分摊结果时，用户**必须**能知道每一笔钱是**按什么规则**落到某个站点/层上的。

- 分摊分四步，不可跳步：资源直挂 → 规范标签 → 域树推断 → 未分配。每步的覆盖量与金额都要可见。
- 每条分摊记录标注命中的步骤与规则版本；规则变更后，历史账期仍按当时版本可查。
- 展开任一站点/层，可看到构成它的成本行（服务、资源、金额、口径、精度）。

**验收**
- 四步的金额之和等于当期总额。
- 把某资源的规范标签删掉（模拟标签缺失），下一次重建后该资源金额从第 2 步落到第 3 步或第 4 步，页面可见。
- 历史账期在任何规则版本下都能打开，且显示"按 v1 规则计算"。

#### FR-12 节省建议

**在**查看节省建议时，用户**必须**看到估算依据，而不是一个数字。

- 只允许四类可计算项：闲置资源、未挂载存储、超额预留、跨区流量。
- 每条**必须**给出：估算金额、可读公式（如"闲置 14 天 × 730 小时 × 单价"）、依据数据、所属站点/层。
- 不提供"一键执行"入口；只能查看依据并跳转到资源详情。

**验收**
- 每条建议的公式代入数字能算出展示金额（允许四舍五入误差）。
- 点击建议能跳到资源详情，且该资源在列表里可定位。

### 2.4 漂移

#### FR-13 漂移列表

**在**查看漂移时，用户**必须**同时看到「有多少漂移」和「覆盖了多少资源」，否则会误把"没查"当成"没问题"。

- 列表每行：严重度、资源、属性、期望值、实际值、首次发现、出现次数、状态、可能来源的发布。
- 严重度四档，判定只看两维：属性敏感性 × 是否影响可用性。`CRITICAL`（加密关闭 / 公开访问 / 删除保护关闭 / 全网放通）、`HIGH`（行为改变：内存、超时、并发、缓存、生命周期）、`MEDIUM`（标签、描述、非关键参数）、`LOW`（格式差异）。
- 列表**必须**与覆盖率同屏：`已对账 / 受管资源`，低于 95% 时加"覆盖率不足"角标。
- 支持按严重度、状态、站点/层、通道、关键词筛选；筛选项进 URL。

**验收**
- 任意筛选下都能看到覆盖率，且覆盖率不随筛选变化（它衡量的是整体）。
- 造一条 `CRITICAL` 漂移，结论条与导航徽标同步 +1。
- 把某层排除后，覆盖率下降且未覆盖清单里出现该层。

#### FR-14 漂移详情与处置

**当**用户处理一条漂移时，系统**必须**给他判断所需的全部证据，并要求认领/忽略留下理由。

- 详情展示：期望值与实际值的差异（左右对照，长内容可折叠）、证据来源（文件或 API 字段路径）、首次/最近发现时间、出现次数、可能来源的发布（仅提示，不断言）、关联资源链接。
- 认领（`ACKNOWLEDGED`）**必须**填理由与复核日期（默认 7 天后）；忽略**必须**填理由与到期日。
- 到期后自动恢复为未处理，并产生通知。
- 漂移消失时先进入"待复核"，下一次采集仍不出现才关闭，防抖。

**验收**
- 不填理由无法提交认领，前端与后端都拒绝。
- 忽略到期后，该条重新出现在未处理列表，且能看到"忽略已到期"。
- 差异内容超过 20 行时折叠，展开后可滚动，不撑破抽屉。

#### FR-15 双通道状态

**在**查看漂移时，用户**必须**能分清两条通道各自跑没跑、结论是什么。

- 两条通道并列展示：属性对账（每日）、`plan` 对账（每周）。每条给出上次运行时间、耗时、检查数、结论数、状态。
- 状态四值：成功 / 部分成功 / **未能判断** / 失败。**「未能判断」必须与「0 条漂移」视觉与文案都不同**，不得合并。
- 某层代码基线过期（快照超过 7 天）时，该层的属性对账结论标"基线过期"，不计入漂移数，只计入未覆盖。

**验收**
- 让 `plan` 通道因权限失败，页面显示"未能判断"并说明原因，趋势上不出现 0。
- 基线过期的层在覆盖率里体现为未覆盖，不出现在漂移列表。

### 2.5 发布

#### FR-16 运行列表与详情

**在**查看发布时，用户**必须**看到真实的 CI 运行，而不是手工录入。

- 列表：时间、工作流、模式（plan / apply）、结论、涉及层、变更数、风险级别、操作者。
- `plan` 与 `apply` 视觉可区分（plan 用空心徽标）。
- 详情：作业耗时、变更的资源清单（新增/修改/销毁/替换）、关联漂移、关联安全结论、关联的提交与 PR。
- 资源变更集合由两次代码快照做差得出，**不得**靠解析计划文本。

**验收**
- 一次 apply 结束后 5 分钟内出现在列表，变更数与 `terraform` 输出一致。
- 风险徽标可点开，显示命中了哪条判定规则。
- 无法关联到提交或 PR 的运行显示"未关联"，不编造。

#### FR-17 触发与双人确认

**当**用户要执行一次 apply 时，系统**必须**强制走三步，且不允许一人完成。

- 第一步：预检。展示计划摘要（新增/修改/销毁/替换）、将被销毁的资源数、未处理 `CRITICAL` 漂移数、风险级别。任一为"未知"时**禁止**继续。
- 第二步：提交申请，填写理由。
- 第三步：由**另一名**有权限的用户确认后才会真正触发；同一人确认返回拒绝。申请 24 小时未确认自动失效。
- 触发后平台只观察，不参与执行、不主动取消。

**验收**
- 预检被阻断时，提交按钮不可用，并列出全部阻断项。
- 同一账号完成确认时被拒，且审计里有记录。
- 超过 24 小时未确认，申请状态变为已失效。

#### FR-18 发布指标

**在**查看发布指标时，用户**必须**看到口径，避免指标被"美化"。

- 四个指标：成功率、频率、交付时长（P50/P90）、平均恢复时长。每个都可展开看到公式与统计窗口。
- 口径不可自定义。

**验收**
- 四个指标都能展开公式，公式中的分子分母与列表数据一致。

### 2.6 安全与告警

#### FR-19 安全姿态

**在**查看安全时，用户**必须**看到清单，而不是分数。

- 四类检查：公网暴露面、静态加密与证书、身份与权限、密钥位置。
- 每条给出：规则、类、严重度、对象、证据、修复建议（一句话 + 可复制的片段或命令）。
- **不提供**总分、等级、仪表盘。只给条数与分布（类 × 严重度矩阵，可点）。
- 密钥类结论**不得**展示原文，只显示前 4 后 4 字符与位置。
- 可豁免，豁免需理由与到期日；到期自动复现。
- 未豁免的高危结论会抬高相关层在发布时的风险级别。

**验收**
- 矩阵每一格点进去得到对应清单，且清单条数与格子数字一致。
- 植入一个假密钥能被检出，页面不显示其完整值。
- 豁免到期后结论回列表，且状态是"未处理"而不是"已豁免"。

#### FR-20 告警与事件

**在**响应问题时，用户**必须**知道"现在什么在响、响了多久、去哪看细节"。

- 告警按站点/层分组，同一告警 30 分钟内合并为一条并显示出现次数。
- 每条提供跳转到原生监控系统的链接（带时间范围与筛选条件）。
- 事件流展示平台自身事件（采集完成、漂移新增、发布结束、开关变化），最多 50 条。
- 数据源健康区显示三云与 CI 的新鲜度与降级原因。
- 平台**不提供**告警规则编辑与静默（避免双份规则不一致），只能标记已读。

**验收**
- 同一告警连续触发 5 次，列表只出现一条且次数为 5。
- 跳转链接打开后时间范围与页面显示一致。
- 数据源健康区能看出"哪个源、多久没更新、原因"。

### 2.7 容灾

#### FR-21 切换矩阵

**在**准备容灾时，用户**必须**看到一份"能执行"的矩阵，而不是一张愿景图。

- 每行一个组件：主、备、切换方式、RTO、RPO、上次演练、状态、**前置条件**。
- RTO/RPO **只认演练实测值**；未演练的行显示"未验证"，不显示理论数字。
- 上次演练超过 90 天整行标黄，超过 180 天 RTO/RPO 一并标为"过期"。
- 前置条件未全部验证时，该行视为"不可执行"，并在展开区逐条列出。
- 平台不提供"执行切换"按钮，只给步骤与检查项。

**验收**
- 把某行改成未验证，该行 RTO/RPO 变为"未验证"，且不能作为可用方案被引用。
- 展开任一行能看到全部前置条件及其验证状态。
- 超过 90 天的行有可见的时间警示。

#### FR-22 演练记录

**当**完成一次演练时，用户**必须**能记录实测结果，并让它回到矩阵里。

- 记录包含：日期、范围、覆盖的组件、实测 RTO、实测 RPO、结果（通过/部分/失败）、遇到的问题、偏差原因、后续动作。
- 保存后自动更新被覆盖组件的"上次演练"与 RTO/RPO，并置为已验证。
- 记录可回溯：时间线列表，每条可展开看详情。

**验收**
- 记录一次演练后，矩阵对应行的时间与数值立即变化。
- 实测值与矩阵原值差异超过 20% 时，记录页提示"偏差较大"。

### 2.8 平台自身

#### FR-23 身份与角色

**在**使用平台时，用户**必须**只有两种角色，权限边界清晰。

- `OWNER`：可读全部、可触发发布、可导出、可改配置。`VIEWER`：只读。
- 敏感操作（触发发布、导出、改配置）需要一次短期二次确认（≤5 分钟有效）。
- 登录失败 5 次锁定 15 分钟。
- 会话 8 小时，滑动续期。

**验收**
- `VIEWER` 调用写操作被拒，且审计有记录。
- 二次确认过期后再执行敏感操作被拒。

#### FR-24 审计

**在**发生任何状态变更时，系统**必须**留下可查的痕迹。

- 记录：谁、何时、对什么、做了什么、结果。
- 覆盖范围：触发发布、确认发布、导出、改配置、认领/忽略漂移、豁免安全结论、手动触发采集、记录演练。
- 保留 12 个月，可按人、时间、动作筛选。

**验收**
- 上述每个动作执行后，审计里都有对应记录，字段完整。
- 审计条目不可编辑、不可删除。

#### FR-25 降级与数据新鲜度

**若**任一数据源不可用，系统**必须**继续可用，并把"不知道"明确说出来。

- 页面显示上次成功时间，**不得**把旧数据呈现为"最新"。
- 降级信息在响应中携带，页面用横幅呈现；同一源的横幅不重复叠加。
- 依赖该源的计算（如分摊）标为"基于旧数据"，并给出上次成功时间。
- 平台自身健康检查区分正常 / 降级 / 故障三态。

**验收**
- 断掉一个云的数据源，其余页面与区块正常，受影响区块显示"基于 2 小时前数据"。
- 三个源都断时，页面仍可打开并给出统一提示，不白屏。
- 恢复后无需重启，下一次采集自动回到正常态。

#### FR-26 通知

**当**平台产生需要人处理的事件时，系统**必须**通知到位且不制造噪音。

- 默认只外发三类：`CRITICAL` 漂移、与公网暴露相关的高危安全结论、发布失败。其余为站内信。
- 同一事件对象 60 分钟内只发一条，后续合并为"另有 N 条"。
- 每条通知必须含：一句话结论、影响对象、可点的平台链接、建议动作。缺任一项不发。
- 可按站点设置维护窗口，窗口内不外发（站内信照记）。
- 涉及账号 ID、桶名、分发 ID 的字段在通知正文中脱敏（只留后 4 位）。
- 发送失败重试 3 次，仍失败则页面提示"通知通道异常"。

**验收**
- 连续制造 5 条同类事件，只收到 1 条通知且正文含"另有 4 条"。
- 通知中的链接点开落在对应详情。
- 维护窗口内不外发，但站内信可查。

## 3. 非目标 / Non-goals

| 不做 | 原因 |
| --- | --- |
| 写云资源、执行 apply | 写入口唯一，只能是 CI；平台有写权限就成了最高权限单点 |
| IaC 编辑器 / 在线改 Terraform | 代码是唯一真相，平台只读代码与快照 |
| 自建告警引擎与日志存储 | 告警在各云原生系统，日志在 Loki / 云日志；平台只聚合与跳转 |
| 自动修复漂移、自动切换容灾 | 误判成本高于收益；首期只做"看见 + 建议" |
| 多租户与对外 SaaS | 内部工具，单租户 |
| 给安全打分、给资源打分 | 评分是伪精度，会取代真正的清单 |
| 移动端适配 | 桌面决策工具，窄屏只提示 |
| 成本预测与预算审批流 | 首期只做实际发生额与简单预算阈值 |

## 4. 硬性不变量 / Hard invariants

违反任一条即为缺陷，不接受"下个版本改"。

| # | 不变量 |
| --- | --- |
| 1 | **每个金额必须带口径与精度**，缺一即缺陷；金额可为"未知"，但**不得**用 0 表示未知 |
| 2 | **未分配金额单独成行**，永远不摊进任何站点/层来"抹平" |
| 3 | **「未能判断」不得等同于「0 条」**（漂移、成本、覆盖率三处都适用） |
| 4 | **层号 = apply 顺序**，站点内连续、唯一、无空洞；`02-data` 在 `03-compute` 之前，`04-edge` 在最后 |
| 5 | **图谱节点是（站点，层）**，不引入"服务"这一层抽象 |
| 6 | **每条边必须有来源等级与证据文本**，无证据不入图；弱推断边默认不画 |
| 7 | **未映射的 canonical 类型记"未映射"**，不猜测、不改写云原始类型 |
| 8 | **密钥与凭据原文不入库、不入通知、不上页面**，只留前后各 4 字符 |
| 9 | **平台对云的权限只有只读**；唯一写动作是触发一次 CI，且需双人确认 |
| 10 | **RTO/RPO 只认演练实测值**，未演练标"未验证"，不填理论值 |
| 11 | **降级不隐藏**：数据过期必须显式标注时间，不得把旧数据呈现为最新 |

## 5. 数据与接口概要 / Data and interface outline

> 本节只描述**实体与契约的语义**，不规定表结构、字段类型与实现方式。

### 5.1 核心实体

| 实体 | 说明 | 关键属性 |
| --- | --- | --- |
| 站点 | 可独立销毁/重建的部署单元 | 名称、云、开关、清单哈希、是否合法 |
| 层 | 站点内的 Terraform 根模块 | 目录名、**层号（= apply 顺序）**、类型、依赖、state 位置 |
| 资源 | 三云任一受管对象 | 云、云内标识、云内类型、canonical 类型、所属层、规范标签、原始标签、生命周期状态、首末次出现 |
| 域节点 | 资源域树 | 路径、类型（云/账号/订阅/项目/站点/资源组/层/未归类）、父节点 |
| 栈边 | 层与层的关系 | 起点、终点、来源等级、权重、证据、是否断边 |
| 成本行 | 统一口径后的账单行 | 云、账期、服务、资源、金额、币种、**口径**、**精度**、账期状态 |
| 分摊记录 | 成本落到站点/层的结果 | 站点、层、金额、命中步骤、规则版本 |
| 差异桥 | 两类口径的差额分解 | 五类金额、总额、残差 |
| 漂移结论 | 一条属性级差异 | 资源、属性、期望、实际、严重度、状态、次数、通道、基线是否过期 |
| 发布运行 | 一次 CI 运行 | 运行标识、模式、结论、涉及层、变更集合、风险级别、关联提交/PR |
| 安全结论 | 一条可判定检查结果 | 规则、类、严重度、对象、证据、建议、状态、豁免到期 |
| 演练记录 | 一次容灾演练 | 日期、范围、覆盖组件、实测 RTO/RPO、结果、问题、偏差、后续 |
| 事件 | 平台内部事件 | 类型、对象、时间、载荷、投递状态 |
| 审计条目 | 状态变更留痕 | 谁、何时、动作、目标、结果 |

### 5.2 对外接口分组

| 分组 | 能力 | 端点数量 | 说明 |
| --- | --- | --- | --- |
| 身份 | 登录、登出、二次确认、当前用户 | 4 | 会话制 |
| 目录 | 资源列表/详情、域树、站点与层、健康度、开关状态 | 6 | 只读 |
| 图谱 | 图数据（三视图）、影响面、健康度 | 3 | 只读 |
| 漂移 | 列表、详情、认领、忽略、通道运行、覆盖率 | 6 | 认领/忽略为写 |
| 成本 | 汇总、趋势、差异桥、分摊、节省、预算、重建、导出 | 8 | 重建与导出为写 |
| 发布 | 运行列表/详情、变更、预检、提交、确认、指标 | 6 | 后三为写 |
| 观测 | 指标、告警、外链、SLO | 4 | 只读 |
| 安全 | 列表、详情、豁免、汇总 | 4 | 豁免为写 |
| 通知 | 订阅、更新、测试、历史 | 4 | 更新为写 |
| 平台 | 任务、事件死信、配置、审计、切换矩阵、演练 | 9 | 部分为写 |
| 实时 | 事件流 | 1 | 长连接 |

约定（全部接口共用）：

- 列表统一分页，超过 200 条必须分页；导出走单独端点。
- 时间统一 UTC，界面按本地时区展示。
- 金额统一返回「数值 + 币种 + 口径 + 精度」四元组。
- 数据源不可用时**返回成功 + 降级说明**，不返回 5xx，以免整页失败。
- 写操作幂等键与乐观锁（版本号），冲突返回可读提示。

### 5.3 与外部系统的关系

| 外部系统 | 关系 | 只读/写 |
| --- | --- | --- |
| AWS / GCP / Azure 清单与成本接口 | 采集资源、成本、变更事件 | 只读 |
| 各云监控 | 拉取关键指标与告警 | 只读 |
| CI（GitHub Actions） | 读运行记录与产物；触发一次 apply | 读 + 一次 dispatch |
| 代码侧快照 | 读 apply 后的状态快照与计划快照 | 只读 |
| 通知渠道（飞书 / 邮件） | 发送卡片通知 | 写（仅通知） |
| 仓库清单文件 | 读站点与层声明 | 只读 |

平台**不直连** Terraform state 存储，只消费 CI 产出的快照——state 的存储格式不是稳定契约。

## 6. 分期 / Slices

| 切片 | 范围 | 出口判据 |
| --- | --- | --- |
| **S0** | 壳层、导航、总览骨架、资源目录只读（样例数据） | 9 个页面可点通，导航与 URL 一致 |
| **S1** | 三云资源采集、域树、站点与层、栈图谱三视图、影响面 | 资源计数误差 < 1%（S-1 达标），图谱 ≥ 12 条可信边 |

## 7. 界面要求 / UI requirements

统一要求（适用于 9 个页面）：

- **三段式**：一句话结论 → 主视图 → 明细/证据。只有图表没有结论视为未完成。
- **每个数字可点**，落到明细或证据；不可点的数字要在视觉上弱化，避免"看着像能点"。
- 四态齐全且文案不同：加载（骨架）/ 空（说明 + 一个动作）/ 降级（横幅 + 旧数据时间）/ 错误（可重试 + 追踪号）。
- 筛选条件写进 URL；刷新、分享后结果一致。
- 不可逆操作必须二次确认，确认层要写清影响对象数量。
- 视觉：浅色、低饱和、卡片圆角、无阴影分层；正文对比度 ≥ 4.5:1；桌面优先，1280 起三栏。

页面要点（详细版式见原型）：

| 页面 | 主视图 | 必备要素 |
| --- | --- | --- |
| 总览 | 成本趋势（全宽） | 结论条、4 指标卡、异常与待办、成本构成 + 节省 |
| 资源目录 | 列表/树/按层 | 命中/全部、三视图、抽屉详情、未归类可见 |
| 栈图谱 | 关系图 | 三视图、图例与等级、影响面三跳、健康度四项 |
| 成本 | 差异桥 + 趋势 | 口径与精度徽标、未分配行、四步分摊、节省公式 |
| 漂移 | 漂移列表 | 覆盖率同屏、严重度四档、双通道状态、差异对照 |
| 发布 | 运行列表 | plan/apply 区分、变更集合、风险徽标可展开、三步触发 |
| 安全 | 类×严重度矩阵 | 清单优先、证据与建议、密钥脱敏、豁免到期 |
| 容灾矩阵 | 矩阵表 | 未验证标注、90/180 天警示、前置条件、演练记录 |
| 告警与事件 | 分组告警 | 合并计数、原生系统外链、事件流、数据源健康 |

## 8. 验收 / Acceptance

### 8.1 端到端场景

| # | 场景 | 期望 |
| --- | --- | --- |
| AC-1 | 新人第一次打开总览，不点任何东西 | 30 秒内能说出"这个月花了多少、最该先处理哪件事" |
| AC-2 | 从总览的"未处理 CRITICAL 漂移"进入 | 落在漂移页、筛选正确、URL 可分享 |
| AC-3 | 从资源列表打开某资源抽屉，刷新页面 | 抽屉仍在，筛选与页码不变 |
| AC-4 | 在图谱选中 `03-compute` | 右侧给出影响面三跳，第一跳含 `04-edge` |
| AC-5 | 在成本页把口径从分摊切到发票 | 出现差异桥，五类之和等于差额，未分配行为 0 |
| AC-6 | 让一个云的数据源失效 | 页面可用，横幅点名该云与最后成功时间，其他云正常 |
| AC-7 | 同一账号试图确认自己的发布申请 | 被拒绝，审计有记录 |
| AC-8 | 打开一个未演练的容灾组件 | RTO/RPO 显示"未验证"，不作为可用方案 |
| AC-9 | 让两条通道其中一条失败 | 显示"未能判断"，不显示 0 条漂移 |
| AC-10 | 把某站点的清单改成非法（层号重复） | 该站标"清单异常"并给出原因，不展示猜测结构 |

### 8.2 交付判定

一个切片算完成，必须同时满足：

1. 该切片所有 FR 的验收条目逐条通过，且有可复现步骤记录。
2. 四态（加载/空/降级/错误）在该切片涉及的页面上都能触发并正确渲染。
3. 所有金额带口径与精度；所有结论可点开到证据。
4. 不变量 1–11 无违反。
5. 新增接口在 §5.2 的分组表里登记，新增页面要素在 §7 的表里登记。

## 9. 假设、风险与开放问题

### 9.1 假设

| # | 假设 | 不成立时的影响 |
| --- | --- | --- |
| A-1 | 三云都能提供聚合资源清单接口 | 退化为按区枚举，采集变慢但可用 |
| A-2 | 账单能导出到对象存储（明细或汇总） | 成本只能停在汇总级，站点级分摊不可用 |
| A-3 | CI 能产出代码侧快照（状态与计划） | 图谱只能画结构边，漂移只剩属性通道 |
| A-4 | 资源量级 < 2,000、层数 < 20 | 超出后域树与图谱需要分层加载 |

### 9.2 风险

| # | 风险 | 缓解 |
| --- | --- | --- |
| R-1 | 账单管道迟迟不到位，成本页停在汇总级 | S2 允许先上汇总级并明确标注"估算"，后续替换数据源不改界面 |
| R-2 | 分摊口径被业务质疑 | 差异桥强制展示、规则版本化、每个数字可钻到账单行 |
| R-3 | 漂移误报多导致没人看 | 严格的最小单位（属性）+ 忽略规则必填理由与到期 + 误报率进验收 |
| R-4 | 平台自身成为单点 | 只读、可降级、控制面与数据面分离、断源演练进 S4 |
| R-5 | 单人维护，长期腐化 | 每个切片的验收可脚本化；不变量数量控制在 11 条以内 |

### 9.3 开放问题

| # | 问题 | 影响 | 建议 |
| --- | --- | --- | --- |
| O-1 | GCP 侧是否需要独立于 AWS 的观测采集 | 影响断源演练的结论 | 建议 S4 前确认，默认"需要" |
| O-2 | 成本是否需要对内出账（按团队/成本中心） | 影响分摊维度是否要扩 | 首期不做，接口预留 `cost-center` 维度 |
